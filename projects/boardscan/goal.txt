Author boardscan, a read-only CLI in src/boardscan.py that surveys agent task boards: it reads every <root>/projects/<dir>/.agent/task_board.json (root defaults to the current working directory, override with --root PATH; boards are read-only, never modified, no network, no third-party deps -- stdlib argparse only). There are exactly three tasks, each EXTENDING the same implementation file src/boardscan.py while keeping every function the earlier tasks added intact (a task's final module content must satisfy all previously pinned tests as well as its own), and each task owns its OWN distinct authored test path, one file per task which no other task may share: T-DATALOADER owns tests/test_loader.py (data loading and manifest reading: read every <root>/projects/*/.agent/task_board.json, skip missing boards, per-project task list access); T-RENDERER owns tests/test_rendering.py (task row formatting and escalation diagnosis parsing); T-CLI owns tests/test_cli.py (argparse wiring, exit codes, --json mode). INVOCATION: python src/boardscan.py [--project NAME] [--root PATH] [--json]. DEFAULT OUTPUT: one section per project, each beginning with a header line '== <project-name> ==', then one row per task with exactly the columns [id, TITLE, STATUS, ATTEMPTS, DEPS]: STATUS is the task status verbatim if it is one of done|pending|failed else '?'; ATTEMPTS is the integer retry_count; DEPS is the task's dependencies rendered as comma-space-joined ids or '-' when empty; TITLE is the task title verbatim; columns are separated by ' | '; a task row whose id/title contains a newline is rendered with newlines replaced by spaces. ESCALATION DIAGNOSIS: after the table, for every task whose last_feedback string starts with 'DIAGNOSIS:', print one indented diagnosis line '  DIAGNOSIS: <cause> (confidence=<confidence>) remedy=<remedy>' where a raw well-formed feedback has the shape 'DIAGNOSIS: cause (confidence=0.95) remedy=fix_env' -- cause is the text before the ' (confidence' marker, confidence the token after confidence=, remedy the token after remedy=; a malformed or non-DIAGNOSIS last_feedback never produces a line. ORDER: projects in sorted directory-name order; tasks in board file order; --project NAME prints only that project's section and errors with exit code 2 and stderr 'no such project: NAME' when absent. JSON MODE: --json prints a UTF-8 pretty-printed JSON array of objects [{'project': name, 'tasks': [{'id','title','status','retry_count','dependencies'}]}...] in the same deterministic order, plus a top-level 'diagnoses' key on each project object holding each extracted {task_id, cause, confidence, remedy, raw}. EXIT CODES: 0 normal; 1 when a project's board exists but is unreadable JSON (message to stderr, other projects still processed); 2 when the root directory or the --project target does not exist. TESTS (authored, offline, fixtures only): build synthetic tmp_path workspace fixtures covering: empty projects dir (no sections), a project with done+pending+failed rows, deps rendering, diagnosis extraction with cause/confidence/remedy, malformed-board JSON -> exit 1 while other projects still render, --project missing -> exit 2 stderr message, --json round-trip equality with table content; each fixture lives in the test file that owns it. No live workspace reads in tests.
